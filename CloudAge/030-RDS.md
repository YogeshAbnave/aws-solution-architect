# 📘 Amazon RDS (MySQL) – Technical Overview & Best Practices

---

## 🧠 1. **What is Amazon RDS?**

Amazon RDS is a **fully managed relational database service** that supports multiple database engines and handles:

* Provisioning
* OS patching
* Backups
* Monitoring
* Scaling
* Disaster Recovery

---

## 🛠️ 2. **RDS Supported Engines**

1. **MySQL**
2. **PostgreSQL**
3. **MariaDB**
4. **Oracle**
5. **SQL Server**
6. **Amazon Aurora (MySQL/PostgreSQL-compatible)**

---

## 🎯 3. **Core Features of RDS**

| Feature                   | Description                                       |
| ------------------------- | ------------------------------------------------- |
| **Managed**               | No manual DB provisioning, patching               |
| **Point-in-Time Restore** | Restore to any second within the retention window |
| **Monitoring Dashboards** | Via CloudWatch or RDS Console                     |
| **Read Replicas**         | Up to 5 replicas to improve read performance      |
| **Multi-AZ**              | Automatic failover support                        |
| **Storage**               | Backed by **EBS (gp2/gp3/io1/io2)**               |

---

## 🧾 4. **Backups and Snapshots**

### 🔁 **Automated Backups**

* Enabled by default
* Daily **full backup**
* **Transaction logs** every 5 mins
* Retention: **7 days** (extendable to **35 days**)

### 🖼️ **Manual Snapshots**

* Triggered manually
* **Stored until deleted**
* Useful before updates or deployments

### 🕒 **Point-In-Time Restore**

* Restore database to **any second** in retention period

---

## 🏗️ 5. **Architecture: Multi-AZ & Read Replicas**

### 🧱 **Multi-AZ (High Availability)**

* Primary in **AZ1**, standby in **AZ2**
* **Synchronous replication**
* Automatic failover
* No read access to standby

### 📖 **Read Replicas (for Scalability)**

* Asynchronous replication
* **Eventually consistent reads**
* Used for read-only apps
* Up to **5 replicas** allowed
* **Within same AZ**, **Cross-AZ**, or **Cross-Region**

---

## 📊 6. **Scaling**

| Scaling Type             | Description                                              |
| ------------------------ | -------------------------------------------------------- |
| **Vertical Scaling**     | Change instance type (e.g., t3 → m5), CPU/RAM            |
| **Storage Auto Scaling** | Automatically increase volume size (based on thresholds) |

> **Conditions for auto storage scaling**:

* CPU > 70%
* Free storage < 10%
* At least **6 hours** since last resize
* Running out of IOPS or disk

---

## 🔁 7. **Replication Behavior**

| Replica Type             | Description                              |
| ------------------------ | ---------------------------------------- |
| **Read Replica**         | Read-only, async, for analytics/reports  |
| **Can promote replica?** | ✅ Yes, you can make it a new **master**  |
| **Consistency**          | Eventual consistency (read lag possible) |

---

## 🧳 8. **Migration to RDS**

| Component          | Detail                                       |
| ------------------ | -------------------------------------------- |
| **Legacy App**     | Connected to local MySQL                     |
| **Migration Plan** | Modify connection string to RDS              |
| **Code Changes**   | Minimal or none, just DB host/port/user/pass |
| **Tools**          | AWS DMS, mysqldump, native replication       |

---

## 🧾 9. **Use Cases**

| Scenario                        | Recommendation                               |
| ------------------------------- | -------------------------------------------- |
| **Production App (Read/Write)** | Use **Multi-AZ** RDS                         |
| **Reporting App (Read-heavy)**  | Use **Read Replicas**                        |
| **Disaster Recovery**           | Use **Multi-AZ + Cross-Region Read Replica** |
| **Auto-scaling Reads**          | Add **read replicas on demand**              |

---

## 🌐 10. **Cross-AZ & Cross-Region Costs**

| Case                     | Cost Incurred?                     |
| ------------------------ | ---------------------------------- |
| **Same AZ Replica**      | ✅ Network cost applies             |
| **Cross AZ Replica**     | ✅ Additional AZ data transfer fees |
| **Cross Region**         | ✅ Costly (inter-region transfer)   |
| **Read Replica Updates** | ✅ Charged for data replication     |

> 📌 Use **AWS Pricing Calculator** for detailed estimates:
> 👉 [https://calculator.aws.amazon.com](https://calculator.aws.amazon.com)

---

## 🛡️ 11. **Maintenance Window**

* Time slot when:

  * Minor version upgrades
  * OS patching
  * Parameter changes are applied
* Define this during DB creation
* Downtime may occur during this window

---

## ❌ 12. **What RDS Is NOT**

| Not Available In                                   | Comment                         |
| -------------------------------------------------- | ------------------------------- |
| **Serverless (except Aurora)**                     | MySQL RDS is **not serverless** |
| **Manual Storage Control (if auto scaling is ON)** | Admins only set max limits      |

---

## 🧮 13. **Planning & Architecture Summary**

| Component        | Recommendation                                        |
| ---------------- | ----------------------------------------------------- |
| **RDS Primary**  | Single-AZ for dev, Multi-AZ for prod                  |
| **Read Replica** | Enable for analytics                                  |
| **Storage**      | io1/io2 for high IOPS, gp2 for general                |
| **Auto Scaling** | Enable storage auto-scale                             |
| **Snapshots**    | Schedule before any change                            |
| **Monitoring**   | Use CloudWatch (CPU, Disk, Free Storage, Replica Lag) |
