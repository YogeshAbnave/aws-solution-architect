## 🗂️ **AWS S3 Complete Documentation with Hierarchy**

---

### 🔷 **1. Introduction to S3**

* **Full Form:** Amazon Simple Storage Service (S3)
* **Purpose:** Object storage service that offers scalability, data availability, security, and performance.

#### ✅ Common Use Cases:

* Backup and restore
* Data lakes
* Static website hosting
* Big Data analytics
* Media storage

---

### 📁 **2. Core Concepts**

#### 📦 **2.1. Buckets**

* Container for storing objects
* Globally unique name
* Naming Rules:

  * DNS-compliant
  * Lowercase only
  * 3–63 characters

#### 🧱 **2.2. Objects**

* Stored data in a bucket
* Includes:

  * **Key** (filename/path)
  * **Value** (data)
  * **Metadata**
  * **Version ID** (if enabled)

---

### 🛠️ **3. S3 Operations**

* **PUT** – Upload
* **GET** – Download
* **DELETE** – Remove object
* **LIST** – List content
* **HEAD** – Metadata only
* **COPY** – Copy across regions

---

### 📂 **4. Storage Classes**

| Storage Class       | Use Case           | Durability | Availability |
| ------------------- | ------------------ | ---------- | ------------ |
| S3 Standard         | Frequent access    | 11 9s      | 99.99%       |
| Intelligent-Tiering | Unknown access     | 11 9s      | 99.9–99.99%  |
| S3-IA               | Infrequent         | 11 9s      | 99.9%        |
| One Zone-IA         | Infrequent in 1 AZ | 11 9s      | 99.5%        |
| Glacier Instant     | Archive access     | 11 9s      | 99.9%        |
| Glacier Flexible    | Cold archive       | 11 9s      | —            |
| Deep Archive        | Deep cold storage  | 11 9s      | —            |

---

### 🔐 **5. Security**

#### 🧾 **5.1. Access**

* IAM policies
* Bucket policies
* Block Public Access
* ACLs (legacy)

#### 🔑 **5.2. Encryption**

* In Transit: TLS
* At Rest:

  * SSE-S3
  * SSE-KMS
  * SSE-C
  * Client-side encryption

---

### 🔄 **6. Versioning**

* Keep all versions
* Recover overwritten/deleted objects
* Required for replication

---

### 🔁 **7. Replication**

#### 🔄 7.1 Cross-Region (CRR)

* Backup across AWS regions

#### 🔁 7.2 Same-Region (SRR)

* Compliance/logging

**Requirements:**

* Versioning enabled
* IAM role with replication permission

---

### 🚦 **8. Lifecycle Management**

* Automates storage class transitions and expirations
* Can delete old versions, abort failed uploads

---

## 🧰 **💡 CLI: Create S3 Bucket + Lifecycle Rule**

---

### ✅ Step 1: Create a Bucket

```bash
aws s3api create-bucket \
  --bucket your-bucket-name \
  --region us-east-1 \
  --create-bucket-configuration LocationConstraint=us-east-1
```

---

### ✅ Step 2: Enable Versioning

```bash
aws s3api put-bucket-versioning \
  --bucket your-bucket-name \
  --versioning-configuration Status=Enabled
```

---

### ✅ Step 3: Create Lifecycle Rule JSON

Save this as `lifecycle.json`:

```json
{
  "Rules": [
    {
      "ID": "TransitionAndExpire",
      "Filter": {
        "Prefix": "logs/"
      },
      "Status": "Enabled",
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "GLACIER"
        }
      ],
      "Expiration": {
        "Days": 365
      },
      "AbortIncompleteMultipartUpload": {
        "DaysAfterInitiation": 7
      }
    }
  ]
}
```

---

### ✅ Step 4: Apply Lifecycle Rule

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket your-bucket-name \
  --lifecycle-configuration file://lifecycle.json
```

---

### ✅ Step 5: Verify the Rule

```bash
aws s3api get-bucket-lifecycle-configuration \
  --bucket your-bucket-name
```

### 🌲 **16. S3 Hierarchy Format**

```markdown
S3
├── Bucket (my-data-bucket)
│   ├── Folder (/2025/)
│   │   ├── Subfolder (/June/)
│   │   │   ├── logs-17-june.csv
│   │   │   └── error-17-june.json
│   ├── Permissions (ACL / IAM / Policy)
│   ├── Versioning: Enabled
│   ├── Lifecycle Rules
│   │   └── Move to Glacier after 30 days, expire in 365
│   ├── Event Notifications
│   ├── Replication (CRR/SRR)
│   ├── Encryption (SSE-S3 / KMS)
```
